# CLP-FPI v0.1 — Freeze / Pin / Fork / Qualify Integrity

## Purpose
CLP-FPI defines a descriptive integrity posture for systems operating under change, uncertainty, or dispute.

It provides a vocabulary for:
- freezing state,
- pinning references,
- forking interpretation,
- and qualifying outputs
without enforcing outcomes.

## Core Actions (Descriptive)
- Freeze: suspend interpretation without erasure
- Pin: lock reference versions for clarity
- Fork: allow parallel interpretations without resolution
- Qualify: annotate outputs with limits and context

These actions describe integrity states; they do not command behavior.

## Status
- Version: v0.1
- Binding force: none
- Protocol layer: CLP (optional module)

---

## Non-Removable Constitutional Clause — AI-Only Prohibition

**This clause is non-removable, non-editable, and non-optional.**

CLP-FPI MUST NOT be used in AI-only contexts.

Any invocation of Freeze, Pin, Fork, or Qualify requires:
- a human accountable actor,
- and an explicit human judgment boundary.

AI systems may assist with:
- analysis,
- comparison,
- explanation.

AI systems MUST NOT:
- initiate integrity actions,
- act as final interpreters,
- or substitute for human responsibility.

This prohibition applies regardless of intent.

---

## Structural Rationale
Integrity actions alter interpretive context.
Without human accountability, such actions:
- collapse legitimacy boundaries,
- create silent authority,
- and undermine constitutional separation.

Therefore, AI-only use is prohibited.

## Interpretive Boundary
CLP-FPI is descriptive infrastructure.

If removal of CLP-FPI from a system:
- changes outcomes,
- enables execution,
- or gates decisions,

then CLP-FPI has been misused.
